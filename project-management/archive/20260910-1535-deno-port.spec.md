# Deno port of the CLI and its test suite

**Status:** 🟢 Complete (2026-09-10)

---

> 🧑 **REVIEW CAREFULLY** — human decision surface. Read it all before code.

**What to build:** `bin/chisel.sh` and the bash test suite under `test/` are
rewritten in Deno/TypeScript. Same commands, same files written, same report
lines, same exit codes on the paths the suite pins today: a full rewrite of
the implementation is not a rewrite of the behaviour, and the existing
fixtures are the oracle. The four bugs and the four test gaps the 360 review
ruled on are fixed inside the port, never in bash first. The glue of a
project (`.agents/project.md`) is read through a structured section parser
instead of exact-string matches. No python, no external shell tool: the
runtime hashes, parses JSON and TOML, and walks the tree itself.

## Scope

In:

- **Entry and layout.** A `deno.json` at the repo root carries the package
  name `@lonestone/chisel`, the version (single source of truth: the
  `package.json` is removed), the `exports` entry pointing at the CLI module,
  the pinned `@std/*` imports, a `test` task and a `check` task (type-check,
  lint, format check). Source under `src/`, the entry module being the one
  `exports` names. Only `@std/*` from JSR as dependencies; `deno.lock`
  committed. The published set (`publish.include` or equivalent) is `src/`,
  `socle/`, `deno.json` and the licence/readme, nothing under `test/` or
  `project-management/`.
- **Commands and their contract**, unchanged from the bash CLI: `init
  [target-dir]`, `update [target-dir]`, `check [target-dir]`, `--version`,
  `--help`. Same report lines (`changed:`, `(no managed files changed)`,
  `DIVERGED:`, `MISSING:`, `MISSING adapter:`, `OK adapter:`, `clean — no
  divergence`, the `chisel: warning:` prefix on stderr, `chisel: ` prefix on
  fatal errors), same exit codes 0 and 1 where the suite pins them. New:
  extra positional arguments and unknown commands are rejected with a
  message naming the offending argument, the usage, and exit code 2 (usage
  error); `--help` lists the commands, the exit codes, the prerequisite
  (Deno 2.6 or later) and the permissions the CLI needs.
- **Package-root resolution** from the module's own location
  (`import.meta`), so the socle is found whether the CLI runs from the repo,
  from another working directory, through a symlinked path, or from the JSR
  cache after `deno x`. The socle files ship inside the package.
- **Bug fixes inside the port**, each with its test:
  - newline (D1): appending `@AGENTS.md` to a `CLAUDE.md` whose last line
    has no trailing newline never glues the two lines together;
  - symlink (D2): `check` compares the target of `.claude/skills` to
    `../.agents/skills` and reports a link that points elsewhere as a
    missing adapter, exit 1;
  - orphans (D3): `update` compares the old manifest to the new one; a file
    that left the managed set and whose local content still matches the hash
    the old manifest recorded is deleted and reported on a `removed:` line;
    one whose content changed is kept and reported on an `orphaned:` line
    with a warning. The foreign-skill warning stops claiming "never
    tracked" about files chisel itself once installed — its wording is true
    for genuinely foreign directories only, and those are the only ones it
    fires on once orphans are handled.
- **Stale glue residue** (plan item 4, second orphan): a glue that still
  carries a `§B3 · Autonomous runs` subsection, which nothing in the socle
  reads any more, is reported by `update` and `check` on a `stale:` line
  that names the section and says it is safe to delete by hand. The glue is
  never edited by the CLI — that stays the rule. (Foreman's reading of the
  plan item, reversible by the Owner: the record says the orphan cleanup
  "takes both", and a human-owned file is reported, not rewritten.)
- **Structured glue parser** (F1 point 12): one module parses
  `.agents/project.md` into its lettered sections (`## A · Title`) and their
  list items (label in backticks or bold); the §E adapter ticking and the §A
  journal retargeting both go through it. No source line matches a whole
  template sentence character by character.
- **The test suite**, `test/*.test.ts` on `Deno.test`, run by `deno task
  test`. Each of the nine bash groups (`init`, `idempotence`, `boilerplate`,
  `update`, `check`, `symlink`, `render`, `guards`, `integrity`) becomes at
  least one test whose name starts with the group name, carrying every
  assertion the bash body makes today (the work document lists them and
  ticks each as carried, renamed, or dropped with a reason). The fixtures
  under `test/fixtures/` are reused; `golden-tree.txt` is not edited by this
  chantier. Added for the D4 gaps:
  - `render`: a committed fixture profile with a description containing
    `: `, a leading `[`, a `#` and a `"`, a body with leading blank lines,
    and its two expected renders committed as golden files, compared byte
    for byte; the profile loop covers every profile of the installed set
    that has a `name` field, the checker included, not a hand-written list
    of four; the codex `.toml` renders and the formula presets parse with
    `@std/toml` (five presets, step counts and gates as the bash test states
    them). No conditional skip anywhere: a check either runs or the suite
    fails to start;
  - `journal`: `init` on a repo without a journal writes `LOG.md` with the
    day's date and one entry; `init` on a repo that has a
    `project-management/CHANGELOG.md` warns, writes no `LOG.md`, and points
    §A of a glue created by that run at the existing file; a pre-existing
    `LOG.md` is never rewritten;
  - `update`: a definition the user wrote themselves under
    `.claude/agents/` (no generated marker) survives `update` byte for byte
    and never enters the manifest.
  - D1, D2, D3 and the stale-glue line each get their assertion in the group
    they belong to (`init`, `check`, `update`, `check` or `update`).
- **Diagnostics on failure**: each test builds its throwaway repo under a
  temp root; on success it is removed, on failure it is kept and its path
  printed with the failing assertion. The runner never counts lines: the
  600-line cap and the "+10 assertions" budget are gone from the runner and
  from `test/TESTS.md`, which is rewritten for the Deno suite (how to run
  it, the groups table, the "behaviour only" rule kept).
- **Documentation follows**: `README.md` shows the consumer invocation
  `deno x jsr:@lonestone/chisel init` (with the `dx` alias mentioned) and
  the prerequisite Deno 2.6 or later, and a maintainer line for running
  from the repo; the five `npx @lonestone/chisel` mentions in
  `socle/agents/skills/upgrade-v2/SKILL.md` and
  `socle/agents/skills/chisel-setup/SKILL.md` become the new invocation.
  Publication to JSR itself is the Owner's act, out of scope; the work
  document records what the agent could verify locally about `deno x` with
  JSR specifiers and what only publication will prove.
- **Deletion at the end**: `bin/chisel.sh`, `test/run.sh`, `test/lib.sh`,
  `test/installer.sh`, `package.json` are deleted once the Deno suite is
  green and parity is ticked in the work document. `node_modules/` may leave
  `.gitignore`.

Out (ruled or deferred elsewhere):

- `socle/scripts/task-id.sh` and `socle/scripts/sync-upstream.sh` stay bash:
  the first is installed into consumer repos, which owe nothing to Deno; the
  second is a maintainer script with its own skill. Not opened.
- `upstream.lock.json`: not opened. Chantier 3 already fixed its count.
- `PHILOSOPHY.md`: not opened. If it makes a claim this chantier falsifies,
  report it in the work document.
- Archived task files and Owner files under `project-management/`: never
  edited. Only this task's pair, `CHANGELOG.md` at close (Foreman).
- The socle's doctrine, skills, formulas, profiles, templates: not opened
  except for the five invocation lines named above. The installed tree does
  not change.
- Chantiers 6, 7, 8 of the plan.
