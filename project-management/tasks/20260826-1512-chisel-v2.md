## Context

The factory design chantier is DONE: the decision map (`fb-3kk`, 14 tickets,
closed 2026-08-26 in `../factory-bench` beads) fully specifies "chisel, un
repo, des modes" — a rework of THIS repo, not a chisel-bis. v2 gives chisel a
**matrix of modes**: piloting (Controlled/Silent | Controlled/Active | Auto —
an *invocation posture*, not a config) × coordination (markdown | beads
embedded | beads server — *repo state*, additive). The three rules and
`workflows.md` are recomposed into an ambient discipline core + two versioned
formulas + skills; agent roles get canonical profiles with per-tool generated
definitions. Current consumers land in Controlled × markdown with **zero
behavioural change** (parity proven at prototype level).

All decisions are already grilled and human-validated — this task *translates*
the chantier, it does not reopen it. Sources are linked, not copied (see
Implementation Decisions).

## Seams

- **The CLI** (`chisel init|update|check`): black-box on fixture repos, file
  tree in → file tree out — extended to profiles, formulas, generated
  definitions
- **The generated `.agents/` layout**: the contract every tool reads
- **The glue** (`project.md` §B1–B3 + `user.md` cascade): the single runtime
  indirection — rules/skills/formulas resolve through it, never hardcode
- **The formula-as-checklist seam**: an agent with NO bd executes the TOML top
  to bottom; gates read "stop and ask"
- **The bd CLI seam** (beads mode): the convention is observable from
  `bd show` / audit trail alone

**Audit round** (2026-08-26 evening — adversarial Fable audit of b05574d,
report `../factory-bench/research/audit-fable-v2.md`, decisions grilled with

- **Corrective slice 08 created** (installer guards, test legibility,
  referential integrity, supervised preset, proposal door) — runs before
  05/06 ; beads enforcement folded into 05 ; wording items folded into 07.
- **Vocabulary: "a default + options", the matrix is retired.** chisel has a
  default behaviour; two options add to it: beads (the status database) and
  auto (permission not to wait). Three workflow presets: `chisel-default`
  (sync gates, human in the loop), `chisel-supervised` (auto with ONE async
  human gate on spec approval — the big picture; the Owner does not review
  program design), `chisel-auto` (no gates, escalation only). **"Factory" =
  auto × beads** — the only combination that REQUIRES beads (queues, lanes,
  async gate lists); plain auto (one chained session: architect plans,
  spawns mason, review, commit) needs no beads.
- **🧑 means the zone's OWNER, not "the human"** — ownership follows
  authorship of the approval: in default the human approved spec+plan (his
  zones); in auto the Architect authored them (his zones — Mason escalation
  terminates there, the human never hears of it); in supervised the human
  approved the spec (his) while the plan is the Architect's. The Brief is
  ALWAYS the human's. Escalation climbs to the owner of the contested zone,
  one rung at a time; the Owner rung's mechanics: a dated ⚠️ line in LOG.md
  + (beads mode) a blocking `escalation` bead assigned to the Owner. No new
  artifact.
- **The proposal door** (Cursor-article insight): profiles must explicitly
  allow proposing beyond-scope improvements — without an explicit door agents
  never propose large refactors and quality decays. → slice 08.
  **FINAL rule (Owner, after reading Cursor's agent-swarm article —
  supersedes the intermediate versions)**: Cursor's "intentional breakage"
  (patch core out-of-scope + comment, compiler propagates) is REJECTED here
  — no swarm absorbs the breakage, human review does. Their signal→dedicated
  refactor-task mechanism is kept. The rule:
  1. Every discovered refactor — useful OR necessary — is REPORTED one rung
     up, always, even when the agent can do without. Information is never
     swallowed.
  2. The report carries three assessments: size; risk (core code? outside
     my scope? wide impact?); and "can I deliver my task cleanly without
     it, or will the result be ugly?".
  3. The receiver decides, never the reporter. Architect on a Mason report:
     small and within what he signed → inscribe in-task OR create a
     refactoring task BEFORE it; too big or risky → do NOT do it, report
     one rung up with his own assessment. The upper rung's verdicts always
     include "noted, later — your task is urgent, proceed".
  4. Hard rule: very core code, out of scope, wide impact → hands up, never
     on one's own initiative.
  5. Reporting is not waiting: if the task stays cleanly deliverable, the
     agent continues while the report travels. It stops only when
     delivering cleanly is impossible without a ruling.
- **Master Architect (future role, noted not built)**: the ownership
